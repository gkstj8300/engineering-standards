# 코드 주석 가이드라인

모든 소스 코드의 주석 작성 기준이다. 언어와 관계없이 적용하며, 예시는 TypeScript로 든다.
프론트엔드 코드에서는 [frontend.rule.md](frontend.rule.md) R18("기본 무주석, WHY만")을 이 문서로 구체화한다.
규칙이 충돌하면 사용자 직접 지시 > 프로젝트 로컬 규칙 > 본 문서 순서를 따른다.

## 1. 핵심 원칙

- 기본값은 주석 없음이다. §3~§5에 해당하지 않으면 한 줄도 쓰지 않는다.
- 주석이 필요해 보이면 먼저 변수·함수 이름을 더 분명하게 바꾼다.
- 무엇(What)은 코드가 보여 준다. 주석에는 그렇게 작성한 이유와 맥락(Why)만 쓴다.
- 프로젝트에서 쓰는 용어로 쓰고, 줄일 수 있는 만큼 줄인다.

## 2. 쓰지 않는 주석

### 2.1 코드를 그대로 읽어 주는 주석

```typescript
// BAD
const user = await fetchUser(userId); // 유저 정보를 가져옵니다.
if (!isLoggedIn) return; // 로그인되어 있지 않으면 종료합니다.
```

### 2.2 설명조의 사족

```typescript
// BAD
// 에러가 발생하는 것을 방지하기 위해 예외 처리를 추가해 두었습니다.
```

### 2.3 버전 관리 시스템이 아는 정보(작성자·날짜·변경 이력)

```typescript
// BAD
/**
 * 작성자: 개발자
 * 내용: 결제 연동 로직 수정
 */
```

### 2.4 주석으로 숨겨 둔 코드

쓰지 않는 코드는 주석 처리하지 말고 삭제한다. 복구는 버전 관리 시스템(예: Git)으로 한다.

## 3. 쓰는 주석

직관적이지 않은 이유나 숨겨진 맥락을 전할 때만 쓴다.

### 3.1 비즈니스 맥락과 정책 제약

```typescript
// GOOD
// 환불 기간은 결제일이 아니라 배송 완료일부터 센다(이용약관 제7조).
```

### 3.2 버그 회피·우회 로직

```typescript
// GOOD
// iOS Safari 스크롤 튐 방지를 위해 repaint를 강제로 유도한다.
```

### 3.3 불변식과 제약

```typescript
// GOOD
// discountRate는 항상 0~1이다(서버 계산값). 범위 밖이면 계산 로직 버그다.
```

### 3.4 출처 추적 주석

디자인·API 계약의 출처를 남기는 주석은 허용한다. Figma 출처는 [figma-implementation.rule.md](figma-implementation.rule.md) D5 형식을 따른다.

```typescript
// GOOD
// figma: 20:183 Card/Product
// 계약: docs/api/orders.md#create-order
```

### 3.5 법적 고지와 도구 지시

- 라이선스·저작권 헤더처럼 법적으로 필요한 주석은 허용한다.
- 도구 지시 주석(`eslint-disable`, `@ts-expect-error` 등)은 설명 주석이 아니다. 피할 수 없을 때만 쓰고 같은 줄에 이유를 남긴다(예: `// eslint-disable-next-line no-console -- CLI 출력`). 프론트엔드는 R2를 먼저 따른다.

## 4. TODO / FIXME

- 임시 조치나 미완성 부분은 `// TODO(<이슈 ID>): <내용>`, `// FIXME(<이슈 ID>): <사유>` 형식으로 남긴다. 이슈가 없으면 이슈 ID 자리에 담당자를 적는다.
- 프론트엔드에서 실 API를 연동하면 Mock·임시 폴백은 같은 PR에서 모두 제거한다([frontend.rule.md](frontend.rule.md) A1). TODO로 남겨 두지 않는다.

## 5. 공개 API 문서화(선택)

- 모듈 밖으로 공개하는 컴포넌트·함수·타입(예: FSD slice의 `index.ts`, `shared/`의 export)에는 필요할 때 용도와 제약만 담은 한두 줄의 문서 주석(TSDoc, JSDoc, docstring 등)을 쓸 수 있다.
- 내부 구현 주석은 §2, §3을 그대로 따른다.
- 타입으로 표현할 수 있는 것은 주석 대신 타입으로 드러낸다.

## 6. 에이전트 실행 규칙

1. 코드를 제출하기 전에 자명하거나 불필요한 주석이 남아 있지 않은지 확인하고 지운다.
2. 기존 코드의 주석은 작업 범위 안에서만 정리한다. 관련 없는 파일의 주석을 일괄 삭제하지 않는다.
